# py-run

Docker-контейнер для запуска Python-скрипта с собственными зависимостями.

Всё, что нужно, лежит в одной папке `./data`, которая монтируется в `/data`:

```
data/
├── myscript.py        # ваш скрипт (при первом запуске создаётся шаблон)
├── requirements.txt   # ваши модули (при первом запуске создаётся шаблон)
└── venv/              # создаётся автоматически, не трогайте
```

## Как это работает

1. При старте контейнер создаёт виртуальное окружение `/data/venv` (один раз).
2. Если `requirements.txt` изменился — выполняет `pip install -r requirements.txt` в этот venv.
   Если не изменился — установка пропускается, запуск почти мгновенный.
3. Запускает скрипт из venv.

Поскольку venv лежит в volume, при перезапуске и **пересоздании** контейнера (и даже обновлении образа)
пакеты заново не скачиваются.

## Быстрый старт

### Docker Compose

```yaml
# docker-compose.yml
services:
  py-run:
    container_name: py-run
    image: ghcr.io/codinv/py-run
    network_mode: bridge
    init: true
    volumes:
      - ./data:/data
    environment:
      - TZ=Europe/Moscow
      - PY_SCRIPT=./myscript.py   # <-- имя скрипта внутри ./data
    restart: unless-stopped
```

### Docker Run

```bash
docker run -d \
  --name py-run \
  --network bridge \
  --init \
  -v "$(pwd)/data":/data \
  -e TZ=Europe/Moscow \
  -e PY_SCRIPT=./myscript.py \
  --restart unless-stopped \
  ghcr.io/codinv/py-run
```

## Использование

1. Запустите контейнер — в `./data` появятся шаблоны `myscript.py` и `requirements.txt`.
2. Впишите нужные модули в `data/requirements.txt` (по одному в строке, можно с версиями) и отредактируйте скрипт.
3. Перезапустите контейнер: `docker compose restart` — новые модули будут установлены автоматически.

Свой скрипт можно назвать как угодно: положите его в `./data` и укажите `PY_SCRIPT=./main.py`.

## Переменные

| Переменная  | Описание                                | По умолчанию    |
|-------------|-----------------------------------------|-----------------|
| `PY_SCRIPT` | Путь к скрипту (относительно `/data`)   | `./myscript.py` |
| `TZ`        | Часовой пояс                            | `Europe/Moscow` |

Параметры pip можно задавать стандартными переменными, например `PIP_INDEX_URL` или `PIP_EXTRA_INDEX_URL`.

## Миграция со старой версии (`./:/app`)

Раньше проект монтировался как `./:/app`. Старая конфигурация продолжит работать после обновления образа:
контейнер увидит маунт `/app` и запустит скрипт оттуда (в логе будет предупреждение `legacy mount /app detected`).
Но `venv` и `requirements.txt` при этом создадутся прямо в вашей папке проекта.

Чтобы перейти на новую схему:

1. Создайте папку `data` рядом с `docker-compose.yml` и перенесите в неё свой скрипт (и `requirements.txt`, если есть).
2. Замените `./:/app` на `./data:/data` в `docker-compose.yml` (или `-v "$(pwd)":/app` на `-v "$(pwd)/data":/data` в `docker run`).
3. Пересоздайте контейнер: `docker compose up -d`.
4. Если в старой папке успел появиться `venv/`, удалите его.

## Полезно знать

- **Удалили пакет из `requirements.txt`?** pip его из venv не удаляет. Для чистого окружения остановите контейнер,
  удалите `./data/venv` и запустите снова.
- **Переустановить всё с нуля** — тоже достаточно удалить `./data/venv`.
- **Обновилась версия Python в образе** или папку `data` перенесли на машину с другой —
  venv будет пересоздан автоматически.
- **Ошибка установки пакета** — контейнер завершится с ошибкой и покажет вывод pip в `docker logs py-run`;
  после исправления `requirements.txt` просто перезапустите контейнер.
- Образ минимальный (`python:slim`): пакеты, которым нужна компиляция (нет готового wheel), могут не собраться,
  т.к. в образе нет компилятора.
- Файлы в `./data` создаются от имени root.
